# Add CDK Mint Option to Root Compose

**Priority:** P2 (production mint option)
**Source:** OVERNIGHT_TASKS.md ID:18
**Location:** new `docker/docker-compose.cdk.yml`, `README.md`

## Problem

`community-generator.ts` can generate CDK-based Cashu mint configs for production use. However, the root `docker-compose.yml` and `npm run setup:cashu` only use Nutshell. Developers and operators who want to use CDK (recommended for production) have no pre-built compose file to work from.

From gap_analyzer: "Generator picks CDK but local stack uses Nutshell — CDK Docker image or config missing from root stack."

## How to Fix

### Step 1: Create docker-compose override for CDK
Create `docker/docker-compose.cdk.yml` as a Docker Compose override:

```yaml
version: '3.8'

services:
  # Override nutshell with CDK mint
  nutshell:
    image: cashubtc/cdk-mintd:latest  # or the correct CDK image name
    container_name: arxmint-cdk-mint
    ports:
      - "3338:3338"
    environment:
      - CDK_MINTD_URL=http://0.0.0.0:3338
      - CDK_MINTD_LISTEN_HOST=0.0.0.0
      - CDK_MINTD_LISTEN_PORT=3338
      - CDK_MINTD_LN_BACKEND=lnd
      - CDK_MINTD_LND_ADDRESS=lnd:10009
      - CDK_MINTD_LND_CERT=/lnd/tls.cert
      - CDK_MINTD_LND_MACAROON=/lnd/data/chain/bitcoin/regtest/admin.macaroon
    volumes:
      - cdk_data:/app/data
      - lnd_data:/lnd:ro
    depends_on:
      - lnd

volumes:
  cdk_data:
```

Note: Look up the correct CDK Docker image name and env vars from the cashu-cdk or cashubtc repositories.

### Step 2: Add npm script for CDK setup
In `package.json`, add:
```json
"setup:cdk": "docker compose -f docker-compose.yml -f docker/docker-compose.cdk.yml up -d"
```

### Step 3: Document when to use CDK vs Nutshell
Update `README.md` (find the setup section) to add:

```markdown
## Cashu Mint Options

**Nutshell** (default, development):
```bash
npm run setup:cashu
```

**CDK mint** (production-recommended):
```bash
npm run setup:cdk
```

**When to use CDK:**
- Production deployments
- When you need higher performance
- When using the production mint configs generated by ArxMint

**When to use Nutshell:**
- Local development
- Quick testing
- CI environments
```
