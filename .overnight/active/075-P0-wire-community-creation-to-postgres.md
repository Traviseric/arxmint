# Wire community creation to persist configs in Postgres

**Priority:** P0 (high)
**Source:** OVERNIGHT_TASKS.md ID 3
**Location:** app/create/page.tsx, lib/community-generator.ts, app/dashboard/page.tsx

## Problem

Community configs are generated by `lib/community-generator.ts` and stored only in Zustand (in-memory). When the user refreshes the page, all generated community configs are lost. The dashboard (`app/dashboard/page.tsx`) currently reads from the Zustand store which is not persisted to the database.

The `prisma/schema.prisma` has a `Community` model that is never used — no API route creates or reads communities from Postgres.

## How to Fix

1. **Create API route `app/api/communities/route.ts`**:
   - `POST /api/communities` — save a community config to Postgres via Prisma
   - `GET /api/communities` — list communities for the current user (session-gated)

```typescript
// app/api/communities/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { prisma } from '@/lib/prisma';

export async function POST(req: NextRequest) {
  const { name, prompt, config } = await req.json();
  const community = await prisma.community.create({
    data: { name, prompt, config }
  });
  return NextResponse.json({ community });
}

export async function GET() {
  const communities = await prisma.community.findMany({
    orderBy: { createdAt: 'desc' }
  });
  return NextResponse.json({ communities });
}
```

2. **Create `lib/prisma.ts`** singleton (if it doesn't exist):
```typescript
// lib/prisma.ts
import { PrismaClient } from '@prisma/client';
const globalForPrisma = globalThis as unknown as { prisma: PrismaClient };
export const prisma = globalForPrisma.prisma ?? new PrismaClient();
if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma;
```

3. **Update `app/create/page.tsx`**: After community is generated, call `POST /api/communities` with the config. Show a success toast or redirect to dashboard.

4. **Update `app/dashboard/page.tsx`**: On mount, fetch `GET /api/communities` and load into Zustand store. Fall back to in-memory store if API fails.

5. **Update `useSovereignStore`** in `lib/store.ts`: Add `loadCommunitiesFromDB()` action that fetches from the API.
